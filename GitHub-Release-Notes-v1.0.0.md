# Overview

This is the first public release of:

**Generalized Structural Trigger and Computational Growth Intelligence (GST-CGI).**

GST-CGI begins with a seemingly local question:

> **Must a Two-Way CCC trigger be represented as String DNA?**

The answer developed in this repository is:

> **No. DNA is one encoding of a CCC trigger, not the definition of a CCC trigger.**

Once this restriction is removed, the trigger can become a richer structural object carrying:

```text
Structural State
+
Comparison Semantics
+
Controlled Behavior
+
Evidence APIs
+
Policy Perspective
```

This leads to the **Generalized Structural Trigger (GST)**.

From there, the research expands beyond trigger representation into a larger structural-intelligence problem:

> **What happens when structural localization reaches a leaf, but the leaf is not yet sufficient for a decision?**

GST-CGI introduces an explicit **Leaf Resolution Gate**:

```text
Structural Leaf
      ↓
Leaf Resolution Gate
      ↓
+--------+--------+----------+----------+
|        |        |          |          |
DECIDE  REFINE  LEFTOVER   DELEGATE
```

This creates two major growth paths.

`LEFTOVER` feeds **Delta Intelligence** and structural growth.

`DELEGATE` can generate a **Leaf Sandbox Package (LSP)** for policy-bounded external computation through **Delegated Structural Unfolding (DSU)**.

These mechanisms lead to the larger concept introduced by this release:

# Computational Growth Intelligence

> **Computational Growth Intelligence is the capability of an intelligent system to construct, refine, validate, delegate, compose, and govern the computational structures through which future intelligence is performed.**

# 1. From DNA Trigger to Generalized Structural Trigger

Earlier Two-Way CCC demonstrations often used String DNA as a compact and intuitive structural trigger.

GST-CGI separates:

```text
Trigger Semantics
```

from:

```text
Trigger Encoding
```

The generalized trigger hierarchy becomes:

```text
String DNA
    ↓
Encoded Trigger
    ↓
Comparable Structural Trigger
    ↓
Structural Trigger
    ↓
Behavioral Trigger
    ↓
Generalized Structural Trigger
```

A trigger may therefore be represented by:

* String DNA;
* sequences;
* trajectories;
* vectors;
* metric objects;
* graphs;
* CallingGraphs;
* state structures;
* policy-aware objects;
* domain-specific structural objects.

The important requirement is not a particular data type.

The important requirement is that the object expose sufficient structural semantics for governed discrimination and dispatch.

---

# 2. Canonical Generalized Structural Trigger

GST-CGI defines the canonical trigger model:

```text
GST = <S, C, B, E, P>
```

where:

```text
S = Structural State
C = Comparison / Metric Semantics
B = Controlled Behavior
E = Evidence APIs
P = Policy / Perspective
```

This changes the trigger from a passive dispatch key into a potential **local structural-intelligence unit**.

A mature GST can answer:

```text
What am I?

How should I be compared?

What evidence supports this interpretation?

What counter-evidence exists?

Under which policy perspective am I being evaluated?

What bounded behavior may I perform?
```

```text
          A         B
```

# 5. Structural Leaf Is Not Necessarily Decision Leaf

A central proposition of GST-CGI is:

> **A structural leaf is not necessarily a decision leaf.**

Structural localization may be complete at the current structural granularity while the requested decision remains unresolved.

Therefore GST-CGI introduces the:

# Leaf Resolution Gate

The LRG evaluates whether the current leaf should:

```text
DECIDE

REFINE

LEFTOVER

DELEGATE
```

The key question becomes:

> **Is the current structural localization sufficient for the requested decision under the active evidence, policy, risk, and computational constraints?**

---

# 6. Decision Sufficiency

GST-CGI introduces **Decision Sufficiency** as a policy-relative concept.

Conceptually:

```text
DS =
f(
    Structural Match,
    Evidence,
    Counter-Evidence,
    Uncertainty,
    Risk,
    Decision Cost,
    Refinement Cost,
    Policy
)
```

This prevents the runtime from equating:

```text
Reached Leaf
```

with:

```text
Ready to Decide
```

The framework therefore separates:

```text
Structural Leaf
```

from:

```text
Decision Leaf
```

---

# 7. REFINE and LEFTOVER

GST-CGI makes an important distinction:

```text
REFINE
≠
LEFTOVER
```

`REFINE` means:

```text
Known need
+
Available differentiation path
```

`LEFTOVER` means:

```text
Unresolved need
+
Insufficient mature structural support
```

This distinction is critical because LEFTOVER becomes a first-class input to structural growth.

This converts unknown structure from discarded runtime residue into a potentially valuable research signal.

# 10. Leaf Sandbox Package

A second major path begins when the current leaf is:

```text
Decision-Insufficient
```

but:

```text
Computation-Sufficient
```

for another authorized intelligence.

GST-CGI introduces the:

# Leaf Sandbox Package

Canonical form:

```text
LSP = <C, T, E, B, P, K, R>
```

where:

```text
C = Structural Context
T = Generalized Structural Trigger
E = Evidence Bundle
B = Permitted Behavior
P = Policy Projection
K = Capability Boundary
R = Runtime Contract
```

The LSP is not a raw serialization of the internal leaf.

It is produced through a bounded projection:

```text
Internal Leaf
      ↓
Policy Projection
      ↓
Context Reduction
      ↓
Capability Reduction
      ↓
Evidence Packaging
      ↓
Resource Bounding
      ↓
LSP
```

It does not automatically receive authority to modify the parent runtime.

---

# 12. Result Is Not Delta

GST-CGI explicitly separates:

```text
Result
≠
Delta
```

A delegated system may return:

```text
Result
```

for the immediate task and:

```text
Candidate Delta
```

for possible future structural improvement.

The Result may be accepted while the Delta is rejected.

The Delta may also be valuable even when the immediate Result is inconclusive.

This separation is important for safe structural learning from external computation.

# 13. Structural Sovereignty

GST-CGI introduces a local authority model for AI-to-AI structural computation.

An external system may be permitted to:

```text
Read Local Context

Compare

Simulate

Generate Tests

Search Counter-Evidence

Produce Results

Propose Candidate Deltas
```

while remaining prohibited from:

```text
Modifying Global Structural Memory

Promoting Candidate Structure

Changing Parent Policy

Expanding Its Own Capability

Disabling Audit
```

This establishes:

# Structural Sovereignty

and supports bounded cooperation without unrestricted authority propagation.

# 16. Growth Automation Is a Separate Axis


# 27. Canonical Principles of v1.0.0

This release establishes the following core principles:

1. **DNA is one encoding of a CCC trigger, not the definition of a CCC trigger.**

2. **A Generalized Structural Trigger may carry state, comparison semantics, controlled behavior, evidence, and policy perspective.**

3. **Plugin supplies domain intelligence; Runtime retains structural authority.**

4. **A structural leaf is not necessarily a decision leaf.**

5. **Leafhood is structural; leaf resolution is policy-relative.**

6. **REFINE and LEFTOVER represent different structural conditions.**

7. **Once Leftover becomes a first-class runtime outcome, Delta Intelligence becomes a first-class runtime obligation.**

8. **A decision-insufficient leaf may still be computation-sufficient for bounded external intelligence.**

9. **Export capability, not authority.**

10. **Result is not Delta.**

11. **External computation may propose structure but does not automatically acquire promotion authority.**

12. **Reasoning computes within structure; Computational Growth can change the structure within which future reasoning occurs.**

13. **Computational-System Growth includes growth of reusable relationships among intelligent computational systems.**

14. **Distributed intelligence does not require distributed authority.**

15. **AI can participate in growing the computational structures and computational systems through which future intelligence is performed.**
